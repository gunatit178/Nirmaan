# Nirmaan website

Static site — the output is still plain HTML with one shared `styles.css`, a
built `tailwind.css`, and a few small scripts, no client-side framework. What
changed: the six pages (`index.html`, `services.html`, `projects.html`,
`process.html`, `technology.html`, `contact.html`) are no longer hand-edited
directly. They're **generated by Eleventy** from `src/*.njk` + one shared
layout (`src/_includes/base.njk`, `nav.njk`, `footer.njk`) and committed as
build output — same convention this repo already used for `tailwind.css`.
Edit the source in `src/`, run the build, commit the regenerated HTML.

## Run locally

Serve the folder over http (opening the files directly also works, but page transitions and the local Three.js copy need http):

    npx serve .        # or any static server, e.g. VS Code Live Server

## Change page content or the shared layout

Edit `src/{page}.njk` for one page's content, or `src/_includes/nav.njk` /
`footer.njk` for the parts shared across all six pages (previously
hand-duplicated 6 times each — see `projects/nirmaan-website/architecture/adr.md`
for why that changed). Then rebuild:

    npm install        # once
    npm run build:html            # regenerates index.html, services.html, ...
    npm run watch:html            # rebuilds on every save + serves locally

Per-page `<title>`, meta description, canonical URL, and which of the shared
scripts (`tilt.js`, `contact-form.js`, `layers-3d.js`, `device-switcher.js`)
load are all set in each page's own front matter block at the top of its
`.njk` file — nothing to hunt for across 6 `<head>` blocks anymore.
`sitemap.xml` is also generated (`src/sitemap.njk`), from the same page list,
so it can't go stale the way a hand-maintained one can.

## Change styles

`tailwind.css` is generated from the utility classes used in the `.njk` templates (and the built HTML, as a fallback). After adding or changing Tailwind classes, rebuild it:

    npm run build:css

Or run both builds together: `npm run build`. (`npm run watch:css` rebuilds on every save.) Hand-written styles live in `styles.css` and inside individual `<style>` blocks in the templates.

## Before going live

1. **Set the real domain.** Search `src/` and `robots.txt` for `[YOUR-DOMAIN]` — it appears in canonical/OG tags (`src/_includes/base.njk`) and `robots.txt`'s `Sitemap:` line. `sitemap.xml` doesn't need a manual edit; it's generated from the same value.
2. **Connect the contact form.** Both forms (`index.html`, `contact.html`) post to the URL in their `data-endpoint` attribute. Create a form at a service such as Formspree, then set it, for example:
   `<form ... data-endpoint="https://formspree.io/f/xxxxxxxx">`.
   Until an endpoint is set the form tells the visitor it is not connected. It never pretends a message was sent. Details are at the top of `contact-form.js`.
3. **Check the share image.** `og-image.jpg` (1200x630) is used for link previews. Replace it with your own artwork if you like.

## What each script does

| File | Purpose |
| --- | --- |
| `page-transitions.js` | Direction-aware page transitions, with a fade fallback for browsers that lack View Transitions |
| `layers-3d.js` | The interactive 3D layer scenes (hero, architecture section). Uses `vendor/three.module.min.js`, falls back to the CDN |
| `tilt.js` | Tilt-on-hover for service and project cards |
| `contact-form.js` | Contact form validation and submission |
| `device-switcher.js` | Device preview buttons on the projects page |

All motion respects the visitor's "reduce motion" setting, and every 3D or motion feature falls back to the plain page if it cannot run.
