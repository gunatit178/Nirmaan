# Business model

Three layers, deliberately in this order.

## Layer 1: Custom software services · IMPLEMENTED (operating today)

The cash engine: business websites, e-commerce, portals, dashboards, internal
tools, automation, AI integrations, custom applications, MVPs. Sold as
fixed-scope proposals with explicit out-of-scope lists and milestone payments.

## Layer 2: Recurring services · PLANNED in the OS (Phase 3); offered by hand today

Every suitable project asks: *is there a legitimate recurring need?* Hosting,
maintenance, monitoring, security updates, backups, analytics, SEO, content,
AI/API usage management, small changes, support. Proposals already carry an
optional maintenance plan. It's shown to the client as optional, never bundled.

Rule: never sell a subscription the client doesn't need. A plan must map to
real ongoing work (patches, backups, monitoring, API spend) or it isn't offered.

## Layer 3: Productization · PROPOSED

```text
Repeated client problem → reusable solution → reusable architecture
→ configurable system → Nirmaan product
```

Triggered by evidence, not ambition. See `strategy/productization.md` for the
criteria.

## Direction

```text
Services → productized services → recurring revenue → reusable IP → software products
```
